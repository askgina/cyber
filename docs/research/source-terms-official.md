# Source terms: CISA KEV, NVD, and the official-notice adapters

**Document research, not legal advice.** This is the official-notice and vulnerability-source portion of [#43](https://github.com/askgina/cyber/issues/43). Code reference: [`625e462`](https://github.com/askgina/cyber/tree/625e462). This report distinguishes access rules, rights to reuse source material, and rights to license it to others. A public page, downloadable export, or attribution line is not itself a license. The recommendations are not implementation changes.

## Where the fields go

- [`build_data.py:444–464`](../../pipeline/build_data.py#L444-L464) pulls a 14-day window, attaches matching notices to curated incidents and writes an unmatched triage queue. [`build_data.py:550–563`](../../pipeline/build_data.py#L550-L563) puts up to 300 notices and the recent KEV items into `site/data.json`. The final English pass can also pass selected strings to the translation subsystem. The translation providers are a separate policy review. A 14-day collection window is not a retention limit.
- [`archive.py:198–239`](../../pipeline/archive.py#L198-L239) retains California, Washington, Oregon, HHS and SEC rows in tracked `pipeline/archive_cache/notice_*.json`. It refreshes older data separately, using up to 200 directory pages for California or Washington. [`archive.py:298–320`](../../pipeline/archive.py#L298-L320) builds entries for `site/archive.json`, retaining shortened notice summaries. Maine and the ransomware.live press feed are not in that notice cache mapping. [`prerender.py:525–547`](../../pipeline/prerender.py#L525-L547) skips standalone `press-attack` pages, but that does not remove the rows from public JSON or prevent attachment to curated incident records.
- [`official.py:282–294`](../../pipeline/official.py#L282-L294) merges same-day rows by normalized organization and prefers a row with a count. It records other sources as links. The archive then copies the **winning fields** into a second source bucket with the other source's label and URL. It can also inherit a breach date from the losing row. This is a provenance defect: one agency could appear to supply a different agency's count or summary. Preserve independent source rows before deduplication, then attach matches separately. Do not apply reuse rules just to the displayed source label.
- The other ransomware.live integrations have the same upstream policy risk. [`build_data.py:56–117`](../../pipeline/build_data.py#L56-L117) reads `/v2/recentvictims`, `/v2/victims/{YYYY}/{MM}` and `/stats`. It retains victim/group identifiers, date, sector, country, links and shortened descriptions in `pipeline/victims_cache.json`, and caches upstream monthly totals in `pipeline/ransom_monthly.json`. The site exposes selected rows and derived counts. [`archive.py:83–130`](../../pipeline/archive.py#L83-L130) also retains monthly and recent victim rows in `pipeline/archive_cache/ransom_*.json` and uses them in `site/archive.json`. Changing just the press adapter does not clear those uses.

## Recommended decisions for #44 and #46

1. **Narrow the blanket CC BY claim.** The [README](../../README.md#data-and-license) and [`prerender.py`](../../pipeline/prerender.py#L770-L778) currently present the compiled dataset as CC BY 4.0. Limit that grant to Cyber's own licensable contributions. Mark CISA KEV fields CC0, label NVD as link-only, identify each filing/notice source, and expressly exclude third-party text and source rights from the grant. Use consistent wording for JSON datasets, Markdown and record pages. Attribution alone is not a substitute for permission.
2. **Keep SEC and state metadata factual and qualified.** Keep the filing link, form and filing date. Label `period_ending` as period of report, not breach date: the SEC adapter currently maps it to `breach_date`. [SEC Item 1.05 guidance](https://www.sec.gov/resources-small-businesses/small-business-compliance-guides/cybersecurity-risk-management-strategy-governance-incident-disclosure) generally requires filing within four business days of a materiality determination, not four days after the incident itself. An 8-K/A updates a filing and should not automatically count as a new incident. Report state notice thresholds and count scopes separately. For HHS, strip `Web Description` from new outputs and rebuild retained data without it unless its provenance and reuse rights are confirmed. Consider asking OCR for a documented export schedule or machine-readable channel.
3. **Address ransomware.live first.** The current terms explicitly cover downstream APIs and files, so a narrower dataset license by itself is not enough. Seek written approval covering public JSON, feeds, Git snapshots, aggregates, accessible archives and commercial status. Otherwise stop the affected ingestion/publication and replace it with independent sources. Review already published caches, generated JSON, R2 snapshots, search indexes, derived pages and repository history. Preserve clear distinction between sourced reporting and unverified claims.
4. **Audit retained material before deciding on history.** Remove restricted or unverified material from current outputs and regeneration inputs first. Identify commits and objects containing copied text and restricted records. A history rewrite may reduce availability in the main repository, but not in existing clones, third-party archives or previously distributed snapshots. Do not rewrite automatically. Document why an origin-only cleanup is sufficient or why a coordinated rewrite is warranted.

This review used published policies, official pages and code inspection. It did not run the collector or test production quotas, filing coverage, or end-to-end exports. No license was inferred from a robots file, a public-records statute alone, a free endpoint or an HTTP 200 response.
